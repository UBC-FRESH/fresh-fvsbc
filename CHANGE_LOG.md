- Launched P2 (Contracts and prototype): parent issue #10, child issues #11 and #12, branch `feature/p2-contracts-prototype`.
- P2.1 started: read `canada/bc/BC.trf`, `canada/bc/bcspp.f`, and `canada/bc/blkdat.f` in a sparse clone of the pinned fork at `ef5fa84`. Two claims were wrong in a row. `BC.trf` is a Stand Visualization System plant-form asset, not a tree-list format; and `bcspp.f` is dead code that the BC build does not compile and nothing calls. The real sources are the BC variant's `TREFMT` tree-record format and its `JSP` list of 15 species codes, both in `canada/bc/blkdat.f`, matching `MAXSP =15` in `PRGPRM.F77`. Found that PyFVS's default treelist format differs from the BC default, including `A4` against `A3` for the species field, and that PyFVS injects its own `TREEFMT` when a keyword set lacks one. Recorded with provenance in `notes/reference/bc-treelist-and-species.md`; `notes/scope.md`, the `ROADMAP.md` next-steps note, and the P2.1 issue body are corrected, and the second scope change is commented on the issue.
- P2.1 completed: wrote five reference contracts under `docs/reference/` — the tree-list input, the keyword set, the outputs, the provenance record, and the `nemora` ingestion. Each names the revision it was read at and separates what is verified from what is not. Added `CODE_OF_CONDUCT.md` and `CITATION.cff`, so the validator reports `0 error(s), 0 warning(s)` for the first time. Found that the BC build includes `dbsqlite` (52 source-list entries), and that `DATABASE` at slot 108 of `base/keywds.f` enables 32 named, typed SQLite tables, which makes the database the output contract's primary target rather than the fixed-width reports. Also found that `base/keywds.f` misspells `SALVAGE` as `xSALVAGE`, and that the `SITECODE` keyword carries BC site input through option 94 of `canada/bc/initre.f`.
- P2.2 build spike. **The BC variant builds**, which ADR 0001 had left in doubt, but adding `bc` to the variant matrix is not sufficient. Four defects: `meson_options.txt` rejects `bc` at configure; the BC source list carries 12 Windows-only `fire/cfim` sources needing `tchar.h`; `numpy.f2py` cannot parse `canada/bc/BCPLOT.F77`, which `blkdat.f` includes by a vestigial `INCLUDE`; and PyFVS's `src/api/fvs_step.f90` calls `cubrds`, which no BC source defines. The first three are patched and the build completes, producing `fvsbc.cpython-312-x86_64-linux-gnu.so` with `variant_libs = {"BC":"fvsbc"}`. The fourth blocks the import with `undefined symbol: cubrds_`, and is left as a scope decision for `P3`. Also found that the BC source list has 1 `volume/` entry against 155 for `pn`, recorded as a question rather than a finding. Evidence in `notes/reference/fvsbc-build-spike.md`; the recipe is ADR 0004.
